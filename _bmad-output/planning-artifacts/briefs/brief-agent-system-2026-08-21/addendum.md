# Product Brief 补充

## 后续技术方向候选

负责人补充：后续实现应考虑使用 TypeScript。

这是一项待架构阶段评估的技术方向，不是当前 Product Brief 的产品决定；本阶段仍不涉及 CLI、Schema、IR、适配器或具体实现架构。进入技术设计时，应结合目标运行环境、客户端集成面、类型与测试支持、分发方式和长期维护成本，明确比较 TypeScript 与其他允许语言；在完成该评估前，不把 TypeScript 写成既定架构。

## 现有 CAP 的证据地位

负责人判断：此前 Python CAP 很可能存在大量问题，不应将其实现作为后续建设的可信基线。

因此，现有 CAP 仅可作为以下材料：

- 已暴露问题和真实 bad case 的来源；
- 已尝试产品概念的可行性证据；
- 后续需求与验收设计的反例输入。

它不得因“已经实现”而自动成为目标架构、迁移基线或必须保留的行为合同。后续若进入实现，应从已确认的产品目标、范围和验收重新判断；只有经独立验证仍有价值的行为才进入新方案。当前阶段不开展 Python 代码审计、重写或 TypeScript 迁移设计。
