# PRD 结构审阅

## 目的与读者判断

这份文档旨在帮助后续 UX、架构与故事拆分的**人类读者**，先理解 Agent Context Assembly 的产品判断、MVP 边界和验收门，再据此展开设计与实施；审阅采用 Microsoft Writing Style Guide 的清晰、直接、易扫描基线，且不改变任何产品决定。

## 结构模型

选择 **Strategic/Context (Pyramid)**。PRD 应先给结论、状态和范围，再按重要性展开用户与工作流、需求与护栏、验证证据、风险和参考信息。证据应支持前面的产品判断，不应在需求和范围之前占据主叙事。

建议的主干顺序如下：

1. 文档目的与权威边界（压缩为短导言）
2. 产品愿景与核心判断
3. MVP 决策摘要：纳入范围、单一客户端环境
4. 首要用户、JTBD 与核心工作流
5. 核心术语（短表，仅保留理解 FR 所必需的词）
6. 产品能力与功能需求
7. 跨领域质量要求与产品护栏
8. 成功标准、真实任务样本与首轮验收门
9. 明确非目标
10. 风险、已知未知与假设
11. 其余术语参考

## 总影响

- 共 **13** 项建议：2 MOVE、2 MERGE、5 CONDENSE、1 CUT、1 QUESTION、2 PRESERVE；其中“MVP 决策摘要”的 MOVE 与 MERGE 分别处理位置和重复，不重复计入减词。
- 全部高置信度删减与压缩接受后，预计减少 **711–896 词**，占当前 9,646 词的 **7.4%–9.3%**；预计新总词数为 **8,750–8,935**。
- MOVE 与 PRESERVE 项不减少词数；它们的作用是让范围先于细节、证据晚于论点，并保护人类读者所需的心智模型和可验收合同。
- 没有提供硬性长度目标。若把 8,022 当作目标，本轮安全去重仍差 **728–913 词**；不建议在未确认目标前继续压缩 §5 FR、§6 NFR 或 §2 工作流。
- 理解取舍：把完整术语表移后会降低首次查阅便利，因此必须保留短核心术语块；除此之外，建议删除的内容均为重复位置或重复展开，不牺牲产品内容。
