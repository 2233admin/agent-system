# Brief 输入核对

## 结论

PRD 忠实覆盖已批准 Brief 的产品合同、服务对象、双节奏体验、核心资产、公共/私域边界、三层验证、成功标准、非目标和已知未知。核对发现的两项偏差已修正；未发现需追溯旧 brainstorming 或历史材料的具体缺口。

## 已覆盖

- 低频 Context Assembly 与高频 Activation → Context Loading → Task Execution 的闭环；
- Instructions、Skills、MCP 三类核心源资产，以及 Profile 不构成第四类源资产；
- 期望装配、最终结果、运行观察、差异、冲突、裁剪、来源与 Unknown；
- 公共复用与个人私域独立协同，且公共理解不依赖私域原文；
- 装配忠实度、配置适用性、任务结果三层验证；
- Agent 主动调查和推荐、人保留拒绝与高风险决定权；
- 无可信基线前不虚构百分比，以及一次验收、装配干预、无关上下文和失败类型基线；
- Profile、Hard Handoff、每任务 Skill discovery、第四类资产与平台漂移等已知未知；
- Brief 全部明确非目标。

## 发现与处置

1. **首批任务由推荐滑向强制承诺。** 原稿 §8 与 §9 将 T-1、T-2、T-3 固定为 MVP 必做，弱化了 Brief 的“Agent 推荐、负责人确认”边界。已修正为默认推荐；开始采样前用户可以拒绝、替换或补充候选，验收只约束用户接受的首轮集合。
2. **遗漏外部方法包逐项评估要求。** 原稿只在非目标中声明 BMad、SpecKit 不是系统本体，没有明确其价值仍属未知。已在 FR-2 和风险表补入按来源、行为价值、适用边界和真实表现逐项评估的要求。
