# PRD Prose 审阅

## 目的与读者判断

这份文档旨在帮助后续 UX、架构与故事拆分的**人类读者**，准确理解 Agent Context Assembly 的产品判断、MVP 边界、功能合同与验收门，并据此继续设计和实施；审阅采用 Microsoft Writing Style Guide 的清晰、直接、易扫描基线，不改变任何产品决定。

## 风格判断

文档有意采用技术、直接、证据优先的中文语气：以固定英文术语命名核心概念，以 FR/NFR 和可验收结果表达合同，用否定边界、Unknown 与证据层级抑制过度推论。这些选择服务于精确性，应当保留。当前影响理解的问题主要是少量并列关系失衡、修饰范围不明、单次术语漂移和近邻重复；以下均给出能恢复清晰度的最小修正，不做偏好性改写。结构审阅后已删除的 §8.2 不在本轮审阅范围内，也不建议恢复。

| prose | §4.4：“MVP 只承诺一个真实 Agent 客户端运行环境，**稳定名称为**‘OMP Agent 单客户端环境’。” | “MVP 只承诺一个真实 Agent 客户端运行环境，**本文统一称为**‘OMP Agent 单客户端环境’。” | “稳定名称”容易被理解为运行时配置属性；“本文统一称为”明确它是文档内的规范称谓。 |
| prose | FR-1：“**只有重复执行普通任务、且目标、约束、权限和风险没有实质变化时，产品继续复用稳定配置。**” | “**重复执行普通任务时，只有在目标、约束、权限和风险均未发生实质变化的情况下，产品才继续复用稳定配置。**” | 原句的“只有”修饰范围和“且”的连接层级不清。改成“只有……才……”可明确复用需要同时满足的条件。 |
| prose | FR-3：“Profile 只承担稳定配置的激活与复用语义，不被当作第四类源资产，也不要求与**工作模式**一一对应。” | **可考虑：**“Profile 只承担稳定配置的激活与复用语义，不被当作第四类源资产，也不要求与**稳定工作场景**一一对应？” | “工作模式”未定义且只出现一次，邻近正文一直使用“稳定工作场景”。若两者是同一概念，应统一；若不是，应保留原词并补充区别，而不是直接替换。 |
| prose | FR-6：“个人实践者可以检查期望装配与最终结果之间所有已知差异，以及源资产之间可识别的冲突、裁剪、覆盖和 Unknown。” | “个人实践者可以检查期望装配与最终结果之间**的**所有已知差异，以及源资产之间可识别的冲突、裁剪和覆盖；无法判断的部分保留为 Unknown。” | 补出“的”修复定语关系；把 Unknown 与“可识别的冲突、裁剪和覆盖”分开，避免把未知状态误读为一种已识别的资产关系。 |
| prose | FR-9：“稳定配置可以声明完成目标工作需要的上下文入口；个人实践者在任务期从这些入口取得**当前内容**。” | “稳定配置可以声明完成目标工作需要的上下文入口；个人实践者在任务期从这些入口取得**该任务所需的当前内容**。” | “当前内容”的指代范围不明；补出“该任务所需”即可把它与任务期输入绑定。 |
