## F1 [medium] 「机制强制」的覆盖面被写得比实际大

修订以「**规则由机制强制，不靠自觉**」收尾。该结论只在**本仓能控制的范围内**成立。

反例构造：某台机器在**用户级**装了 BMad（Claude Code 同样会从用户级 skill 目录发现 Skill，那不是项目目录，本仓的 `.gitignore` 与 `ides` 配置都管不到）。该机器上的会话不经 `configs` 也照样拿到全部 bmad Skill——「唯一装配路径」在那台机器上退回成一句声明。

本机现状：`~/.claude/skills` 与 `~/.agents/skills` 均不存在（已实测），因此当前不是活跃问题。但机制本身存在，而 AD 目前只列举了项目级的两个路径，读者会把结论理解为无条件成立。

这条**不应**试图去管——本仓无权也无力约束别人机器上的用户级安装。该做的是把结论的适用范围写准，否则将来有人在这种机器上验收第 (2) 步的 parity，会得到一个假阳性（"看，不走 configs 也有 Skill，说明还没退役干净"或反过来"走了 configs 也一样，说明没差别"）。

**处置：** autofix —— 把强制范围限定为本仓可控面，并把用户级／机器级安装列为已知的外部限制与第 (2) 步 parity 验证的取证前提（验证须在无用户级 BMad 安装的环境中进行，否则结论不可信）。
