- (direction) Why：Agent 需要把低频配置建立、高频可信复用和 Bad Case 演进收敛为最小防漂移闭环，使 OMP Agent 在不复制动态任务/私域内容的前提下稳定获得必要且不过载的能力与上下文。
- (capability) CAP-1 | intent：Agent 能在有界触发条件下主动调查、抽象并提出可区分候选和明确推荐，由用户裁决。| success：触发时给出默认 2~3、最多 4 个候选；每项含来源、行为价值、适用工作、边界、差异、依据、风险、Unknown；用户可拒绝/补充/纠偏，只有高风险、权限、不可逆或价值取舍升级。
- (capability) CAP-2 | intent：用户能保存带有限变体的稳定配置，引用源资产和结构化任务输入入口而不复制原始内容。| success：配置记录适用工作、必要 Instructions/Skills/MCP、变体、边界、来源和入口；任务内容、私域原文、凭据仍由原载体拥有，公共产物不复制。
- (capability) CAP-3 | intent：用户能分别看到期望装配、最终结果、运行观察、差异与 Unknown，并理解重复激活为何相同或变化。| success：配置/安装、发现/启用、连接/批准、本次激活、实际调用/生效分层；缺失、额外、禁用、覆盖、预算裁剪及影响可见；外部状态变化有证据。
- (capability) CAP-4 | intent：用户能以低摩擦复用已验证配置，并在声明输入或外部事实实质变化时重新判断。| success：普通复用无逐项能力选择、无重复输入、产品确认至多一次；必需入口在执行前可见新鲜度/权限；实质变化或阻断性 Unknown 不静默沿用旧结论。
- (capability) CAP-5 | intent：负责人能按静态/机械、受控集成、真实任务三层证据判断配置必要、充分且不过载。| success：仅当三层直接证据作用域一致、必要/充分/不过载均通过且无阻断性 Unknown 时宣布 Verified；无关上下文与任务期干预有记录。
- (capability) CAP-6 | intent：负责人能用固定任务、基线和跨 Session 可比样本判断稳定配置是否改善真实任务。| success：T-1/T-2/T-3（无合适 T-3 时记录理由后用 T-4）每项有 1 基线+2 稳定样本，至少 1 个稳定样本来自新 Session；按固定可比性键分组并记录 SM-1~6 与反指标。
- (capability) CAP-7 | intent：Agent 能把 Bad Case 作为有界证据推动配置演进，而不恢复被悬置概念或增加任务特判。| success：Bad Case 引用失败/差异证据、适用边界和拟议变化；只有明确裁决才创建新修订/规则；旧决定及 supersedes 链保留；默认扩张清单不被个案激活。
- (capability) CAP-8 | intent：任意后续 Session 能追溯配置、激活、判断、证据、Unknown 与决定替代链，而不继承旧授权或动态任务状态。| success：持久记录可按稳定 ID 关联事实、推论、决定、证据和 Unknown；决定变更以追加替代表达；新 Session 只读取事实，不继承确认、授权或任务内容。
- (constraint) Clean-slate：MVP 只支持 OMP Agent；现有 Python CAP 仅作 Bad Case 证据，不是需求、架构或迁移基线。
- (constraint) 稳定配置只引用 Instructions、Skills、MCP 和结构化任务输入入口；禁止持久化或公开复制动态任务内容、私域原文与凭据。
- (constraint) 期望、结果、观察、差异与 Unknown 必须分层；安全性、可信度和任务适用性不得由已配置/已连接自动推导。
- (constraint) 普通复用逐项能力选择为 0、重复输入为 0、产品确认至多 1；机械检查优先，但不得以代理信号替代真实任务证据。
- (constraint) 最终 ARCHITECTURE-SPINE.md 为 adopted companion；实现必须遵守其 AD-1~AD-18，包含 TypeScript 原生 OMP 扩展、六边形边界、SQLite 权威、激活状态机与验证作用域。
- (direction) Non-goal：不构建 OMP/Claude CLI/Codex CLI 配置等价层、多客户端 SPI、远程同步、共享服务、产品遥测或 Python CAP 迁移兼容层。
- (direction) Non-goal：Profile 语义、Hard Handoff、每任务实时 Skill Discovery、动态子 Agent 装配和第四类核心资产不作默认修复；仅在新 FR、真实证据和明确裁决后重开。
- (assumption) 首要用户画像沿用 PRD 当前描述，待首批真实任务样本复核；不据此扩张能力。
- (question) 完成最小样本后，SM-1 首次正式验收通过率、SM-2 干预率和 SM-3 无关内容/能力出现率的量化接受门槛是多少？
- (decision) SPEC.md 保持五字段内核；生成 glossary.md 与 validation-contract.md 两个 spec-authored companions，并采用最终 ARCHITECTURE-SPINE.md 作为 adopted companion。
- (capability) CAP-1 补充：只有新工作场景、已知能力不足或有证据的 Bad Case 触发候选调查；单纯发现、历史存在或技术可行性不得扩张范围。
- (capability) CAP-2 补充：Instructions/Skills/MCP 三类资产不要求齐全；稳定配置必须显式列出不装配能力；有限变体继承共同边界，仅改变已声明差异。
- (direction) Non-goal 补充：不建设业务知识/Memory-RAG/任务资产平台、核心资产分类扩张、taxonomy/Canonical IR、公共配置共享、团队治理/商业化/Catalog 或方法包系统本体。
